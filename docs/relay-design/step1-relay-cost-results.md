# Step 1: optimistic Zcash→Cardano header relay, cost test (box only)
Written Mon Nov 2, 2026, 12:10 AM ET. Code and raw outputs are in `/workspace/zeutxo-step1-relay-cost/`.

## Verdict: PASS on cost, with a major security caveat

**The cost test passes.** One relay batch per Cardano tx fits easily inside the per-tx compute limits:
- **Post-NU7: 8 headers/tx** uses 38.7% of tx memory and 24.0% of CPU.
- **Fee:** about 1.40 ADA per tx, about **604 ADA/day** post-NU7. That is a measured fee formula applied to measured units and tx bytes.
- **Inclusion proof** (escrow release): about 2.5% of memory and 1.4% of CPU.

**What limits throughput is Cardano's 16,384-byte tx size, not compute.** Each Zcash header is 1,487 bytes because the 1,344-byte Equihash solution is inside it.

**Caveat:** the relay skips Equihash ("optimistic"), so a fake header only needs SHA256d ≤ target. That costs about 2.2×10^12 hashes per header. A fraud proof that verifies Equihash on Cardano would take an estimated **~129–257 txs** per disputed header (from the measured BLAKE2b cost below). So the optimistic relay is cheap to *run* but needs either:
- an interactive/bisection fraud game, or
- a validity proof (step 3)

before it can be called secure. See §5.

  - MTP and future-time rules: 117/117.
  - Merkle root from txids: 145/145.
  - Derived chainwork equals the API chainwork after 1/5/10/20/50/117 headers.
- **Aiken:** `aiken check` passed **41/41**, including:
  - full batches of up to 117 real headers;
  - expected-failure tests: tampered merkleroot, wrong parent, finalize before window, too few confirmations, wrong Merkle path;
  - BLAKE2b with Zcash's Equihash personalization (`ZcashPoW`, n=200, k=9), matching Python `hashlib`.
- **Simulated txs:** every batch tx in §3 evaluated successfully. A tx with one tampered header byte **failed** as expected.

Two costs sit on top of the fees:
- **Min-ADA locked in branch UTxOs:** about 5.6 ADA (pre) or 9.2 ADA (post) per batch [estimate: datum + ~110 B output overhead]. That is **≈713 or ≈3,988 ADA/day locked** unless branch UTxOs can be reclaimed. Research code never spends them. Fix: add a "burn branch token after it is > K blocks behind canonical, refund to the submitter recorded in the datum" path.
- **Anchor txs:** `Propose` measured 626,763 mem / 201M CPU (3.8% / 2.0%, unit harness), and `Finalize` 0.6% / 0.4%. Negligible at, for example, hourly promotion.

**Other measured costs:**
- **Inclusion proof** (escrow release), unit harness (calls the validator directly, without ScriptContext Data decoding; simulated batch txs came in *lower* than the harness): **418,507 mem (2.5%), 137,953,035 CPU (1.4%)**. Real block 3,538,812: 10 txs, 4-level tx path, 4-level header path, 5 confirmations. Each extra Merkle level is one double-SHA256 + concat, which is cheap. **Well under the 20% bar.**
- **v1 vs v2:** v1 post-NU7 with 9 headers cost 16.3M mem (99%) versus v2's 7.0M. Re-scanning the 102-entry windows per header is what made v1 expensive. `median11` sorting is about 238k mem per header and is the next optimization target.

## 5. Security finding: the cheap relay needs a fraud-proof path
- **What a fake header costs.** Without Equihash, a forged header needs SHA256d(1487-byte header) ≤ target. At bits `1b7da58e` (block 3,538,900) that is **≈2.24×10^12 ≈ 2^41 hashes per header** (computed).
  - Bitcoin ASICs can't run this 1487-byte layout directly. A GPU running roughly 3 SHA-256 compressions per try, with midstate, could plausibly do one header in minutes to tens of minutes [estimate, not benchmarked].
  - So an attacker renting GPUs could build a heavier fake branch faster than real Equihash miners extend the real chain. The challenge window **alone does not secure this relay**.
- **Equihash on Cardano, measured unit.** One BLAKE2b compression with the Plutus V3 bitwise builtins costs **2,058,686 mem / 2,082,873,031 CPU** (12.5% / 20.8% of the tx limit). The Plutus `blake2b_256` builtin can't be used: Zcash uses a 50-byte output and personalization, which the builtin doesn't support. The same applies to ZIP 221 history-tree hashes.
- **Full Equihash check [estimate].** 512 indices means about 513 compressions (with midstate) ≈ 1.07×10^12 CPU. That is **~129 txs** at 4 compressions per tx, or **~257 txs** at ≤50% CPU, roughly 170–350 ADA per disputed header. It excludes collision and ordering checks, and a smarter word representation could cut it maybe 2–4× [unmeasured].
- **Ways forward:**
  - (a) An interactive bisection game over Equihash tree nodes: the submitter commits to intermediate XORs, so each round needs only a few compressions.
  - (b) A cheap partial fraud proof for crude fakes (a lower-level collision failure needs few hashes) [analysis].
  - (c) The step-3 validity proof replacing Equihash entirely.

## 6. Limitations
- Research code only: not audited, no bootstrap or one-shot genesis, no branch garbage collection.
- The NU7 activation-boundary difficulty transition (window 17→102) is not implemented.
- No header-time vs Cardano-time sanity bound.
- `Propose` lets anyone reset the timer with a heavier branch. That is intended as the challenge, but it allows liveness griefing by a GPU attacker (see §5).
- Post-NU7 costs use real pre-NU7 headers with W=102 windows (difficulty equality not enforced).
